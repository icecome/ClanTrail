## 修复"点击编辑添加无反应"问题（Phase 2 持续）

### 用户反馈
用户强制刷新后反馈：可添加图片（但无预览），添加墓地、编辑墓地、添加人物、编辑人物点击无反应，控制台无告警。

### 诊断过程
1. **代码审查**：TombDetailPage.tsx、MapPage.tsx、styles.css 逐行读，代码逻辑和 CSS 都正确（Modal 有 `position:fixed; inset:0; z-index:100`，按钮 onClick 绑定正确）。
2. **实证测试**：用 puppeteer-core + 系统 Edge 无头测试，发现：
   - 详情页编辑墓地/编辑人物（card点击）程序点击后 Modal 正常弹出 ✅
   - 添加人物按钮因 textContent 含 `+` 前缀导致字符串匹配失败（误报）
   - **MapPage 添加墓地 toggle 是真 bug**：`setAdding((v) => !v)` 点击后按钮文字不变，toggle 失效

### 修复
1. **MapPage 添加墓地**（`web/src/pages/MapPage.tsx`）：
   - 移除 toggle 模式（`adding` 状态保留供地图 click 用，但不再由按钮控制）
   - 改为弹出 Modal 表单：预填地图中心坐标，填写名称，一键保存（`api.createTomb`）
   - 用户不再需要"点按钮→点地图"两步操作，交互更清晰

2. **图片预览**（`web/src/pages/TombDetailPage.tsx`）：
   - 选择文件时立即用 `URL.createObjectURL(file)` 生成预览 URL
   - 存入本地 `previewUrls` state（`Record<id, url>`）
   - 渲染 `<img>` 而非纯文字占位（无预览的照片仍显示占位文字）
   - 刷新后预览丢失（因无真实文件上传），后续做真实上传

## Tomb Keeper 功能拓展头脑风暴（产品战略团队）

### 任务
用户觉得功能单调，不知拓展方向。从 C 端用户视角发散，克制商业化（个人开发者/初创团队定位）。

### 流程（工作流4 产品头脑风暴）
- 建立团队 product-tomb-keeper-brainstorm（主理人方向明）
- 5 成员并行 brainstorm：瑞思(用户研究)、竞析(竞品)、数析(数据)、析客(需求)、路径(路线图)
- 二次深化：数析-2(验证矩阵)、析客-2(P0/P1 功能概述)
- 主理人汇总 → 数析验证假设 → 析客转功能概述 → 整合落盘

### 核心结论
- P0 五项：真实照片、数据备份、忌日提醒、家族关系图谱(纯文本→结构化ID关联)、离线地图薄兜底
- P1 精选 7 项：墓位导航、检索筛选、生平时间轴、纪念册PDF、二维码标记、隐私加密锁、账号继承
- P2 长尾 10 项（协作/云祭扫/OCR/口述/AR/平面图/打卡/每日一忆/治丧/寻亲）
- 北极星指标：关键祭扫节点准时回流率 + 家族档案完整度（弃用 DAU）
- 护城河：离线优先（无账号/无联网/数据不出设备），所有 P0/P1 飞行模式验收
- 依赖链：Person稳定ID → 照片路径 → 备份包 → 关系模型 → 时间轴 → PDF
- 待裁决（用户拍板）：#10二维码NFR冲突、#11 PIN恢复策略、#5高德ToS、#9 PDF付费探针、#8检索门槛
