# 2026-08-05 工作日志

## Tomb Keeper 项目启动（Phase 1 完成）

- **项目定位**：家族墓地信息管理 APP，地图标记为核心交互（单墓信息/墓主/家族/墓组），离线优先，个人/家族使用。
- **技术栈决策**：Rust + Tauri v2 + React（用户否决 Flutter——对 Flutter Web 界面不满意；否决 Go+Wails+Capacitor——两套原生壳架构割裂）。目标平台：Android + Web（无桌面端）。
- **架构**：Cargo workspace，`src-core` 为共享 Rust 库（不依赖 Tauri/Axum），`web/` 为 React + Vite + TypeScript 前端，后期接入 Tauri 移动端 + Axum Web 服务。

## 已完成

1. **数据模型**（src-core/src/models.rs）：Family / TombGroup / Tomb / Person / Photo 五实体，多态照片关联，UUID 主键，ISO 时间戳。
2. **数据库层**（src-core/src/db.rs）：rusqlite（bundled），WAL 模式 + 外键约束，五张表建表迁移，全套 CRUD，按家族查墓地支持组归属。3 个单元测试全部通过。
3. **React 前端骨架**（web/）：Vite + React 18 + TS 严格模式 + React Router + MapLibre GL 地图。页面：地图主页、家族列表、家族详情、墓地详情。数据层暂为内存 Mock（api/client.ts），预置张家演示数据。

## 技术要点 / 踩坑

- rusqlite `params!` 按最大占位符索引计数：`?1` 重复使用只需传 1 个参数，多传会报 `InvalidParameterCount`。
- MapLibre GL 标记用 `::after` 伪元素旋转补偿实现水滴形 marker。
- 前端 bundle 因 maplibre-gl 达 978KB，后续需代码分割（dynamic import）。

## 追加（17:00 会话：修复前后端链路耦合）

### 用户反馈
- 无法编辑墓地、添加人物、添加墓地、添加照片
- 照片保存报 `HTTP 422`

### 根因定位
1. **照片 422**：前端传 `entity_type: "tomb"`（小写），后端 `EntityType` 枚举默认 serde 为 `"Tomb"`（大写变体名），导致 Axum JSON 反序列化失败。
2. **其他操作“无法”**：后端写操作被沙箱再次拦截为 `attempt to write a readonly database`——背景任务 `run_in_background` 即使带 `dangerouslyDisableSandbox` 也不可靠，SQLite 无法创建 journal 文件。

### 修复
1. `src-core/src/models.rs`：`EntityType` 加 `#[serde(rename_all = "lowercase")]`，前后端统一使用小写字符串。
2. `src-core/src/db.rs`：`TombKeeperDb::open` 自动检测数据库目录是否能创建/删除临时文件；不能时自动降级到 `PRAGMA journal_mode = MEMORY`，避免沙箱下 journal 文件写入被拦截。
3. `web/src/api/client.ts`：错误解析先读 `text()` 再尝试 `JSON.parse`，这样 Axum 的 422 text/plain 错误体能直接展示给开发者，便于定位。
